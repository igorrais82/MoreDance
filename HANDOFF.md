## 1. Что это за проект

`C:\Projects\MoreDance` — мобильное приложение для детей «MoreDance. Спортивные бальные танцы шаг за шагом»:
каталог из 5 танцев, уроки с видео, практика под метроном с камерой-зеркалом, прогресс, PIN-кабинет родителя.

- **Expo SDK 58** (`expo ~58.0.22`), React Native **0.88.1**, React **19.3.0**, expo-router **58**, TypeScript strict.
- Платформы: Android и iOS. iPhone **не проверялся** (нет Mac) — Expo Go из App Store теперь SDK 58, версия проекта совпадает, значит запустится.
- Аккаунты: Expo/EAS пользователь **не входил**, Apple-аккаунта нет.

## 2. Окружение и запуск

```powershell
powershell -File scripts\start-emulator.ps1   # эмулятор Realme_12_Pro_Plus, холодная загрузка, swiftshader
npx expo start                                # Metro; затем клавиша a
```

Важные особенности этой машины:

- **Песочница DSH** блокирует запись в `C:\Users\User\.android`, `C:\Users\User\.gradle`, `~/.npm-cache`, `~/.expo`.
  Поэтому эмулятор, Metro и gradle запускаются только с `sandbox_permissions: danger-full-access`.
  Из-за этого в фоновых задачах их процессы «не видны» ограниченному шеллу, а `adb` иногда показывает `no devices`.
- Права на папку проекта были сломаны (`WRITE_OWNER` отсутствовал) — починены скриптом скилла
  `diagnose-windows-sandbox-acl`. Резервные копии и откат: `C:\Projects\acl-recovery\`.
- Скрипт `scripts/start-emulator.ps1` переписан: по умолчанию **холодная загрузка** + **аппаратный GPU**
  (`-gpu host`, Intel UHD; снапшот на этой машине ронял qemu и восстанавливал чужое приложение на экране).
  Флаг `-FastBoot` возвращает старое поведение, `-SoftwareGpu` — откат на `swiftshader_indirect`.
- **Скорость:** со SwiftShader каждый кадр занимал 89–150 мс (100% janky frames, «Slow issue draw commands»
  в каждом кадре), на `-gpu host` — 17–30 мс (janky 1–14%). Если приложение снова «тормозит и переключает
  вкладки по несколько секунд» — первым делом проверить `adb shell dumpsys SurfaceFlinger | findstr GLES`:
  там должно быть `(Intel) ... Intel(R) UHD Graphics`, а не `SwiftShader`.
- `adb` из ограниченного шелла не умеет писать файлы в проект: снимки экрана делались так:
  `cmd /c "adb exec-out screencap -p > C:\Projects\MoreDance\.expo\shot.png"` с полным доступом.

  Прогресс — мята→синий, Танцор — индиго. В настройках 9 пресетов + «Побережье» (Тиффани→Перу).
- Панель снизу скруглена сверху (26), под приложением градиент `RootBackdrop` — чёрной полосы под панелью нет.

- Кнопка настроек — шестерёнка 56dp без плашки в правом верхнем углу «Сцены» (`app/(tabs)/index.tsx`).

### Экраны и функции
- **«Сцена»**: под-вкладки `Сцена | Выступления и разное` (`src/components/PerformancesList.tsx`).
- **«Взрослые»** (`app/(tabs)/adult.tsx`): список роликов, пока пусто — заглушка «Видео скоро появятся».
- **«Танцор»** (`app/(tabs)/dancer.tsx`): под-вкладки `Танцор | Родитель`; профиль (имя, фамилия, дата рождения

  «Родитель» стал под-вкладкой (в панели его нет, но экран `app/(tabs)/parent.tsx` жив и скрыт через `href: null`).

  во всех экранах и компонентах импорт `Text` заменён на неё.

### Логика
- `src/lib/dancer.ts`: возрастные категории (Дети 1/2, Ювеналы 1/2, Юниоры 1/2, Молодёжь, Взрослые),
  ранги Новичок→E→D→C→B→A→S→Мастер, XP = уроки×40 + минуты×2 + звёзды×15, форматирование даты.
  Проверено в Node: 15.06.2010 → 16 лет → «Юниоры 2», 01.01.2020 → «Дети 1».
- `src/context/DancerContext.tsx` — профиль танцора в AsyncStorage (`moredance.dancer.v1`).
  Имя из профиля подставляется в приветствие на «Сцене».

### 6.1 APK (главная незакрытая задача)

Пользователь хочет APK, чтобы переслать знакомому на Android (по Яндекс Почте он отправит сам;
**я не отправляю письма** — нет доступа к его почте, пароль просить нельзя).

Что уже сделано:
1. `npx expo prebuild --platform android --clean` — папка `android/` пересоздана под SDK 58.
2. Создан `android/local.properties` → `sdk.dir=C\:\\Users\\User\\AppData\\Local\\Android\\Sdk`.
3. В `android/gradle.properties` добавлены таймауты HTTP Gradle (180000).
4. Две попытки `.\gradlew.bat assembleRelease` упали на **скачивании зависимости**:
   `Could not download react-android-0.88.1-release.aar (com.facebook.react:react-android:0.88.1)`
   — `Read timed out` и `Connection reset` с `https://repo.maven.apache.org/maven2/...`.
   Сборка доходит до 241–244 задач, то есть компиляция не проблема — только сеть.

Следующие варианты (по порядку):
- **Повторить сборку**: `cd android; .\gradlew.bat assembleRelease` — кэш уже большой, возможно докачает.
- **Скачать AAR вручную** через `curl.exe -L --retry 5 -C -` в
  `com/facebook/react/react-android/0.88.1/` и подключить локальный maven-репозиторий
  (`maven { url uri("local-maven") }` в `android/build.gradle` перед `mavenCentral()`), плюс `.pom`.
- **EAS Build** (облако, нужен вход пользователя в Expo): `npx eas-cli login`, затем
  `npx eas-cli build -p android --profile preview` — профиль `preview` в `eas.json` уже собирает **APK**.
- Готовый APK после успешной сборки: `android\app\build\outputs\apk\release\app-release.apk`
  (подписан debug-ключом — для установки «с рук» подходит, для Google Play нет).
- При пересылке почтой лучше заархивировать в `.zip`: Яндекс и Gmail часто режут `.apk`.
